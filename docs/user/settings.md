# Settings

Shared controls follow upstream T3 Code, adapted to Coder workspaces. Use the scope picker to select
workspaces or project overrides. Search jumps to a control. Workspace settings live in the remote
workspace; browser preferences follow the browser's existing preference storage.

## Composer

**General → Plan mode** restores Build/Plan, `/plan`, `/default`, and Shift+Tab. Off uses build mode.
**Context window indicator** controls the token-usage meter. It remains enabled by default in
T3 Coder, preserving the fork's existing behavior.

## Starting folder and workspace identity

**General → Add project starts in** sets the folder initially shown by Add Project. Leave it empty
for the workspace home directory. The folder browser's **Home** action returns there if a saved
starting folder is no longer available.

**Workspace icon** chooses a visual identifier shown with the workspace connection. It changes
only the icon, not the workspace's platform or execution behavior.

## Background activity

Scheduling profiles update Git refresh and provider health-check intervals together:

| Profile       | Git refresh | Provider health |
| ------------- | ----------- | --------------- |
| Performance   | 15 seconds  | 1 minute        |
| Balanced      | 30 seconds  | 5 minutes       |
| Battery saver | Disabled    | 15 minutes      |

Change the provider interval in General and the Git interval in GitLab source control. Other
combinations display **Custom**. Zero disables scheduled work; explicit refreshes still run.
Git polling exists only while a repository has subscribers. These profiles do not monitor desktop
battery, power modes, or screen locks. Existing interval settings are preserved until changed.

## Restart recovery

**Continue threads after restarts** is off by default. When enabled, the workspace helper attempts
to resume interrupted provider sessions with saved resume state when it next starts. It does not
reconnect or start a stopped Coder workspace by itself. Archived or deleted threads are excluded.
Recovery sends “Continue where you left off.” through the workspace provider. If recovery fails,
the thread shows an error and can be continued manually.

## Notifications

**System notifications** offers Off, Notifications only, Sound only, and Notifications with sound.
Notifications require browser permission and are generated by the open app; no push server is used.
Foreground in-app alerts are controlled separately. Unsupported or denied system notifications
leave the previous choice unchanged and explain how to proceed.

## Provider and model presentation

Each workspace has one Codex and one Claude configuration. Give either a display name and accent
color in Providers. These controls do not collect credentials or create additional instances.
Long model lists have a filter. Favorites appear first, then visible models, then hidden models;
reordering stays within those groups. Custom models retain their existing editor.

## Keyboard shortcuts

**Keyboard shortcuts** includes Stop current thread, Pin or unpin current thread, and Copy MR URL
or thread ID. Select multiple workspaces to apply an edit to each connected workspace. Reset uses
each workspace's own saved rules.

Saved project actions appear as `script.{id}.run` commands. Assign a shortcut to run that action
in a new terminal in the active thread's checkout. For example, a Test action can run the project's
test command without typing it into a terminal. Actions use the active project's effective command,
including project overrides. Their default condition leaves focused terminal input alone.
